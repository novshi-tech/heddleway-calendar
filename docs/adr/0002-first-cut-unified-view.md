# 0002 最初に作るのは、本人の予定の統合ビュー

- 状態: 案(2026-11-27、直樹の「予定が横断的に見られないのが不便」から)
- 関連: [0001](0001-separate-tool-across-instances.md)、Heddleway の `docs/adr/0008`(アプリの絞った許可。2026-11-13 採用、11-14 実装)

## 背景

0001 は統合ビューと同期の 2 つを決めた。前提の 0008 は採用・実装済みなので、作り始められる。どちらから作るかを決める。

いま困っているのは「自分の予定を 1 か所で見られない」こと(0001 の背景の 1)。直樹の予定は 3 つの組織に分かれている。

| デプロイ | 組織 | カレンダー |
|---|---|---|
| gateway.novshi-tech.com | ノブシテック | Google Calendar(`calendar`) |
| gateway.quzilla.co.jp | くじらキャピタル | Google Calendar(`calendar`) |
| gateway.urban-b.com | UBS | Microsoft 365 の予定表(`graph`) |

## 決定(案)

### 1. 統合ビューを先に作り、同期はあとにする

- 統合ビューは読むだけで済む。口は予定の一覧の読み取りだけで、0008 の未決 1(Graph のサブスクリプションをパスで絞れない)にまだ触れない
- 同期は、統合ビューの土台(デプロイへの接続、予定の読み取り、正規化)の上に足す

### 2. 画面はこのツールが持つ。モバイルファースト

- 0001 の未決 4 は「このツールの Web 画面」に決める。見たいのはスマホで、エージェントを起こさずに開けること
- 1 画面に、今日から 1 週間を時刻順に並べる。予定ごとに組織の色と名前を付ける。PC はあとで崩さず広げる
- 0001 の決定 3 のとおり、開いたときに各デプロイから読み、中身は保存しない

### 3. デプロイは直樹の Cloudflare アカウントに 1 つ

- Workers + D1(D1 に持つのは、デプロイごとの接続(リフレッシュトークン)とサインインのセッションだけ)。TypeScript strict、フレームワークなし
- 使う人が直樹だけのうちは 1 人用。複数人で共有する形は、使う人が出てから決める(0001 の未決 1)

### 4. 口(アプリの定義)

- Google Calendar: `GET ^/calendar/v3/calendars/primary/events$`
- Graph: `GET ^/v1\.0/me/calendarView$`
- 本人のメインのカレンダーだけ(0001 の未決 3 の「最初は各デプロイのメインのカレンダーだけ」)

### 5. 出すもの

- 辞退・取り消しの予定は出さない。仮の予定(未回答)は薄く出す。終日の予定は日の頭に出す。非公開の予定も本人には件名ごと出す(見るのは本人だけ)
